# Constraints

## Infrastructure
- Node.js ^22.6 || ^24 required; npm ^11 (updated 2026-07-15)
- Production served via `node serve.cjs` — static files + Fetch API proxy
- Cloudflare caching disabled via `Cache-Control: no-store` in serve.cjs
- Deployed through cloudflared tunnel; app uses relative API URLs (not localhost)
- Build outputs to `dist/`; `public/` contains pre-build static assets
- Bundler is Vite (`vite build`), migrated from webpack upstream (updated 2026-07-15)
- Test runner is Vitest (`npm test` → `vitest run`), migrated from Jest upstream (updated 2026-07-15)
- Weekly automated upstream sync via `.github/workflows/sync-upstream.yml` — merges `Ajaxy/telegram-tt` master every Monday 09:00 UTC (or manual dispatch), validates with `npm run check && npm test && npm run build:production`, pushes to `master` only if validation passes
- Production URL: `https://interlink.unkndlabs.com`; `serve.cjs` binds port 8445 (added 2026-07-17)

## Rules
- Do not use `null` in TypeScript — enforced by linter
- Do not use conditional spread operators (`...condition && { field }`) — no type checking
- Use template literals for inline `style` prop — Teact does not support style objects
- Use CSS variables for font-weight, never numeric values (`var(--font-weight-medium)`)
- Always use `lang()` for user-visible text — never hardcode strings
- Do not add new libraries — use existing dependencies only
- Do not write tests (per CLAUDE.md)
- API methods should receive full `ApiPeer`/`ApiChat`/`ApiUser` objects, not bare `id` + `accessHash`
- Do not edit `src/lib/gramjs/tl/static/api.tl` — it is autogenerated
- Chat navigation, folder UI, and notifications are restricted to the Telegram folder titled "Main" (case-insensitive) — see `src/util/mainFolder.ts`; fails closed (no-op) if no Main folder exists

## Hazards
- WebView lacks `navigator.locks` — `compatTest.js` is patched to always pass; don't revert this
- `deploy/copy_to_dist.sh` is a bash script and does not work on Windows — `serve.cjs` replaces it
- Fetch extraction uses relative URLs (`/api/...`) — direct localhost URLs break through cloudflared proxy
- `postinstall` clears `.cache/` on every `npm install` — expected behavior, not a bug
- `withGlobal` selectors must not allocate new objects/arrays — defeats memoization
- `openChat` action and `notifyAboutMessage` silently no-op for chats outside the Main folder — if a chat won't open or notify, check `mainFolder.ts` logic before the chat/notification pipeline
- `logs/` is not gitignored and accumulates `error-N.log`/`out-N.log` pairs on `serve.cjs` restarts — 704 files / 1.31 MB as of 2026-09-04, newest pair `error-645`/`out-645` still at 2026-09-03 09:38 (updated 2026-09-04). Properties of this directory, all still holding:
  - The N is a PM2-style restart counter, **not monotonic** — it has reset three times (349→0 on 2026-08-10; 813→~0 between 2026-08-24 09:53 and 16:07; 398→56 between 2026-08-30 05:08 and 08:21), so the newest file by mtime can carry a *lower* number and numbers collide with deleted pairs. Never infer restart count or ordering from filenames; sort by mtime.
  - Between resets N advances in a fixed 9-unit quantum (+9, +18, +36, once ~+54) while adding only one file pair, so the counter overstates restarts.
  - Not every restart writes a log pair, and no-log restarts are now the norm (PIDs 77224 on 2026-08-31 21:23, 63736 on 2026-08-31 02:00, 78424 on 2026-08-30 21:30 all left no file). **Settled 2026-09-05, reconfirmed 2026-09-06:** PID 130668 (2026-09-05 07:40:44) and then PID 112712 (2026-09-05 10:34:23) both started without changing the directory (704 files, newest pair still 2026-09-03 09:38), so `logs/` is not a reliable restart record at all — use process start time on port 8445 to detect restarts, never file mtimes (updated 2026-09-06).
  - Growth is bursty, not daily: a ~67h quiet stretch (2026-08-25 04:17 → 2026-08-28 ~23:00), then 9 restarts in ~8h, then 15 on 2026-09-01 (00:23 → 21:32, counter 218 → 461), 1 on 2026-09-02 02:17 (461 → 470), then 12 more across 2026-09-02 14:39 → 22:18 and 4 on 2026-09-03 00:44 → 09:38 (counter 470 → 645) (updated 2026-09-03).
  - No pairs written since 2026-09-03 09:38 across four consecutive starts: PID 107656 (2026-09-03 17:18) → PID 130668 (2026-09-05 07:40:44) → PID 112712 (2026-09-05 10:34:23), none wrote a pair. Whatever produced the earlier bursts of pairs is no longer running or no longer logging; treat the 2026-09-03 09:38 pair as the last one (updated 2026-09-06).
  - All recent pairs are zero-byte, so the logs say nothing about *why* it restarts. ~215 of the files are non-empty; the largest (`error-16.log`, 1.1 MB) is stale April 2026 `EBUSY` dist-copy stack traces. Check contents before `git add -A`.
- The production server runs under the strap shim `P:\software\bin\interlink.exe P:\software\interlink\serve.cjs`, so its process name is `interlink.exe`, not `node.exe` — filtering `Get-CimInstance Win32_Process -Filter "Name='node.exe'"` will report the server as down when it is up; check port 8445 (`Get-NetTCPConnection -LocalPort 8445`) instead (added 2026-08-29)
- Do not run bare `pm2 jlist` when checking whether Interlink is up — it dumps every managed process's full env, including live API keys and tokens, into the transcript (~300 KB). Interlink is not pm2-managed anyway; check port 8445 or `Get-CimInstance Win32_Process` filtered on `interlink.exe` (added 2026-09-03)
- A stray root-level file named after the port (e.g. `8445`) can appear from a launcher's error-redirection — not part of the app, safe to delete (added 2026-07-17)
- Untracked `serve.js` (repo root) is an incomplete duplicate of `serve.cjs` — no Fetch proxy, no dist-copy step; `serve.cjs` is the canonical production server, don't confuse the two (added 2026-07-17)
- `.worktrees/` can accumulate stray dirs from the `loop` skill (e.g. `loop-1783831370776-db43f9`) that outlive their run — check before assuming it's app-related state (added 2026-07-17)
- Never write prose into `CLAUDE.md` — git tracks it as a symlink (mode 120000), so added text becomes the link target and produces a broken symlink on checkout. Corrupted four times so far (restored 2026-07-24, 2026-07-25 ×2). `AGENTS.md` is also off-limits for fork-local prose (see Key Facts); put Interlink-only agent guidance in `docs/memory/` instead (updated 2026-07-25)
- The corruption source is `strap map`, not a human — `P:\software\_strap\modules\Commands\map.ps1:423-441` appends the `docs/sys/lookup.json` hint to `CLAUDE.md` whenever the marker is absent, with no symlink check. Every `strap map` / chinvex re-index in this repo re-breaks the symlink; restoring with `git checkout -- CLAUDE.md` is a patch, not a fix (added 2026-07-25)
- The corruption is a self-perpetuating loop, so restoring `CLAUDE.md` during `/update-memory` cannot stick: the memory commit itself triggers a chinvex/`strap map` re-index that re-corrupts the file seconds later (confirmed 2026-07-25 — commit 3646b9f22 at 09:17:12, both `CLAUDE.md` and `docs/sys/lookup.json` rewritten at 09:17:15). Once corrupted it stays corrupted — `map.ps1` skips the append when its marker is present, so the re-index fires on every commit but the append only re-fires after a restore. Settled: expect exactly one dirty file (`CLAUDE.md`, 184 bytes, frozen at the 2026-07-25 09:17:15 corruption mtime) and a fresh `lookup.json` mtime after every commit, until `map.ps1` gets a symlink guard. Held unchanged across five consecutive memory commits (d4409868a, 35628c00d, a710c0dad, 54290b8a9, ef40f9f4d — the last at 23:20:11 → `lookup.json` 23:20:14); stop re-verifying it each run (updated 2026-07-28)
- `strap` generates lifecycle artifacts in the repo root (`.strap/`, `start-*.cmd`, `stop-*.cmd`) — gitignored since commit 114374540; don't re-add or hand-edit them (added 2026-08-24)
- `.chinvex-status.json` is stale (last run 2026-06-05) — do not use it to judge whether the lookup index is current; check `docs/sys/lookup.json` mtime instead; gitignored since 2026-09-02 (updated 2026-09-02)
- Chinvex artifacts (`docs/sys/lookup.json`, `.chinvex-status.json`) are gitignored — regenerating them is expected machine output and must never be committed or treated as a working-tree change (added 2026-09-02)
